# Frontend handoff: ข้อมูลพื้นฐาน

เอกสารนี้บันทึกเฉพาะ contract ที่ frontend ยังต้องใช้สำหรับเมนู **ข้อมูลพื้นฐาน** หลังปรับการเชื่อมต่อ API ตามเอกสารล่าสุดแล้ว โดย backend เป็นผู้กำหนดรูปแบบ endpoint และการทำงานภายในที่เหมาะสม

## 7. อัปโหลดเอกสารและรูปภาพ

ปัจจุบัน API คำขอแก้ไขข้อมูลโรงงานรับเฉพาะ JSON metadata ของไฟล์ และกำหนดให้ URL เป็น absolute URL แต่ frontend ยังไม่มี contract สำหรับอัปโหลด binary file เพื่อให้ได้ metadata ดังกล่าว

Frontend ต้องมีวิธีส่งไฟล์ที่ผู้ใช้เลือกและได้รับข้อมูลกลับมาอย่างน้อยดังนี้:

```json
{
  "success": true,
  "data": {
    "title": "ภาพถ่ายหน้าโรงงาน",
    "description": null,
    "link": null,
    "fileName": "factory-front.jpg",
    "fileUrl": "https://example.com/uploads/factory-front.jpg",
    "fileType": "image/jpeg",
    "fileSize": 245760
  }
}
```

Frontend จะนำ metadata ที่ได้รับไปใส่ใน payload คำขอแก้ไขข้อมูลพื้นฐาน:

```json
{
  "formType": "BASIC_INFO",
  "factoryName": "บริษัท ตัวอย่าง จำกัด",
  "address": "99 หมู่ 1 ตำบลตัวอย่าง อำเภอตัวอย่าง จังหวัดกรุงเทพมหานคร 10000",
  "latitude": 13.7563,
  "longitude": 100.5018,
  "eia": "ไม่มี",
  "eiaOther": null,
  "projectName": null,
  "factoryFrontPhotos": [
    {
      "title": "ภาพถ่ายหน้าโรงงาน",
      "description": null,
      "link": null,
      "fileName": "factory-front.jpg",
      "fileUrl": "https://example.com/uploads/factory-front.jpg",
      "fileType": "image/jpeg",
      "fileSize": 245760
    }
  ],
  "factoryLogo": {
    "title": "สัญลักษณ์โรงงาน",
    "description": null,
    "link": null,
    "fileName": "factory-logo.png",
    "fileUrl": "https://example.com/uploads/factory-logo.png",
    "fileType": "image/png",
    "fileSize": 102400
  },
  "remarks": "แก้ไขข้อมูลทั่วไปของโรงงาน"
}
```

ความหมายของ field ที่ frontend ต้องใช้อ้างอิง:

- ไม่ส่ง `factoryFrontPhotos` หรือ `factoryLogo`: คงข้อมูลเดิม
- ส่ง `factoryFrontPhotos: []`: ลบภาพหน้าโรงงานทั้งหมด
- ส่ง `factoryLogo: null`: ลบโลโก้โรงงาน
- ส่ง object หรือ array ใหม่: แทนที่ข้อมูลเดิม

Frontend ต้องได้รับข้อจำกัดของไฟล์ที่แน่นอน เช่น ชนิดไฟล์ ขนาดสูงสุด และจำนวนไฟล์ รวมถึง error response ในรูปแบบมาตรฐาน:

```json
{
  "success": false,
  "error": {
    "code": "FILE_UPLOAD_FAILED",
    "message": "ไม่สามารถอัปโหลดไฟล์ได้",
    "details": null
  }
}
```

## 8. ยกเลิกคำขอแก้ไขข้อมูล

ปัจจุบันเอกสาร API ยังไม่มี operation สำหรับปุ่ม **ยกเลิกคำขอ** และยังไม่มีสถานะปลายทางที่ frontend ใช้แสดงผลว่า **ยกเลิก**

Frontend ต้องมี operation ที่รับ `id` ของคำขอ และใช้ได้กับคำขอที่ยังไม่สิ้นสุดกระบวนการ เช่น `PENDING_REVIEW`, `REVISION_REQUESTED` และ `REVISED_PENDING_REVIEW` ส่วนคำขอที่อนุมัติ ยกเลิก หรือสิ้นสุดแล้วต้องไม่สามารถยกเลิกซ้ำได้

ตัวอย่างข้อมูลที่ frontend ต้องใช้หลังยกเลิกสำเร็จ โดยชื่อ status code ที่แน่นอนให้ยึดตาม contract ที่ backend กำหนด:

```json
{
  "success": true,
  "data": {
    "id": 123,
    "status": "CANCELLED",
    "statusLabel": "ยกเลิก",
    "isOpen": false,
    "updatedAt": "2026-09-04T10:30:00.000Z"
  }
}
```

Frontend ต้องใช้ error response เพื่อแจ้งกรณีไม่พบคำขอ ไม่มีสิทธิ์ หรือสถานะปัจจุบันไม่อนุญาตให้ยกเลิก:

```json
{
  "success": false,
  "error": {
    "code": "INVALID_STATUS_TRANSITION",
    "message": "ไม่สามารถยกเลิกคำขอในสถานะปัจจุบันได้",
    "details": {
      "id": 123,
      "status": "APPROVED"
    }
  }
}
```
