# Frontend: ข้อมูลผู้ติดต่อใน dialog แจ้งความประสงค์

## ขอบเขต

เมนู **ขอเชื่อมต่อ** > ตารางรายชื่อโรงงาน > **แจ้งความประสงค์**

เอกสารนี้บันทึกความต้องการและสถานะการทำ UI ของ frontend เท่านั้น ไม่ใช่ API contract และไม่ได้ยืนยันว่า backend รองรับหรือบันทึกข้อมูลใหม่แล้ว

## สิ่งที่แก้ไข

- เพิ่มช่อง **ชื่อ-นามสกุล** และ **เบอร์โทร** ก่อนช่องเหตุผลเดิม
- หน้าจอขนาดปกติวางสองช่องในบรรทัดเดียวกัน หน้าจอเล็กเรียงลงทีละช่อง
- ช่องเบอร์โทรใช้ `type="tel"` และเก็บเป็นข้อความ เพื่อรักษาเลขศูนย์นำหน้าและเครื่องหมายที่ผู้ใช้กรอก
- เมื่อเปิด dialog ใหม่ ทั้งสองช่องเริ่มว่างและโฟกัสช่องชื่อ-นามสกุล ไม่เติมข้อมูลบัญชีผู้ใช้โดยอัตโนมัติ
- ปิด dialog แล้วล้างค่าทั้งสองช่อง ไม่ใช้ค่าของโรงงานก่อนหน้า
- ระหว่างส่งคำขอ ทั้งสองช่องแก้ไขไม่ได้ เช่นเดียวกับช่องเหตุผลเดิม
- คงข้อมูลโรงงาน ช่องเหตุผล และปุ่มเดิมไว้

## ข้อมูลที่ frontend ต้องการรองรับ

| ช่องบน UI | ค่าที่ผู้ใช้กรอก | สถานะปัจจุบัน |
| --- | --- | --- |
| ชื่อ-นามสกุล | ชื่อและนามสกุลผู้ติดต่อในช่องเดียว | เก็บใน state `intentContactName` เฉพาะขณะเปิด dialog |
| เบอร์โทร | หมายเลขโทรศัพท์ในรูปข้อความ | เก็บใน state `intentContactPhone` เฉพาะขณะเปิด dialog |

ชื่อ state และ `name` ของ input เป็นรายละเอียดฝั่ง frontend ไม่ใช่ชื่อฟิลด์ API ที่ตกลงแล้ว

## สถานะการเชื่อม API

### API ที่ frontend เรียกใช้อยู่

เมื่อกด **ส่งข้อความ** ใน dialog แจ้งความประสงค์ frontend เรียก:

```http
POST /api/v1/eligible-factories/add-requests
```

- Production URL: `https://d-poms.diw.go.th/api/v1/eligible-factories/add-requests`
- Development URL ผ่าน proxy: `/api-proxy/v1/eligible-factories/add-requests`
- Headers: `Authorization: Bearer <accessToken>`, `Content-Type: application/json`, `Accept: application/json`
- ฟังก์ชันที่เรียก: `submitIntentRequest` ใน `ConnectionRequestPage.jsx`

ตัวอย่าง body ที่ frontend ส่งอยู่ปัจจุบัน (ข้อมูลสมมติ):

```json
{
  "factoryId": "10700000525488",
  "reason": "ขอเพิ่มโรงงานเพื่อยื่นคำขอเชื่อมต่อ"
}
```

`factoryId` มาจากโรงงานที่เลือก และ `reason` มาจากช่องเหตุผล โดยตัดช่องว่างหัวท้ายก่อนส่ง ตัวอย่างนี้แสดงพฤติกรรม frontend ปัจจุบัน ไม่ใช่ payload ใหม่ที่รวมข้อมูลผู้ติดต่อ

### ข้อมูลใหม่ที่ยังไม่ได้เชื่อม API

- งานรอบนี้ทำ **UI เท่านั้น** ตามคำสั่ง ยังไม่ได้เพิ่มชื่อ-นามสกุลหรือเบอร์โทรลงใน request payload
- ไม่ได้เปลี่ยนการอ่าน response หรือโค้ด backend ข้อมูล endpoint และ body ด้านบนตรวจจากโค้ด frontend โดยไม่ได้ทดสอบส่งคำขอจริงในงานเอกสารนี้
- การกดส่งยังใช้พฤติกรรมเดิม ค่าจากสองช่องใหม่ยังไม่ถูกส่งไปบันทึก เมื่อปิด dialog ค่าจะถูกล้าง
- ยังไม่ได้กำหนดให้สองช่องใหม่เป็นข้อมูลบังคับ ไม่เพิ่มข้อจำกัดความยาวหรือ validation รูปแบบเบอร์โทร และไม่ใช้ค่าทั้งสองช่องเป็นเงื่อนไขเปิดใช้งานปุ่มส่ง
- ความต้องการในการเชื่อมต่อขั้นถัดไปคือให้ข้อมูลผู้ติดต่อสองรายการนี้ถูกส่งและบันทึกพร้อมการแจ้งความประสงค์ ส่วนชื่อฟิลด์ ข้อบังคับ validation และรูปแบบ response ยังไม่ได้ตกลงในงานนี้
