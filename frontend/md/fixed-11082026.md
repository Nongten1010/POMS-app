# Handoff: การเปลี่ยนแปลงหน้าโรงงานที่เข้าข่าย วันที่ 11/08/2026

เอกสารนี้สรุปการแก้ไข frontend ในเมนู **โรงงานที่เข้าข่าย** เพื่อให้ backend ตรวจสอบและกำหนด API contract ต่อไป

## ส่วนที่แก้ไขใน frontend

### 1. Bottomsheet เพิ่ม/แก้ไข ข้อมูลจุดตรวจวัด

เพิ่มข้อมูลต่อจุดตรวจวัด:

- `เอกสารแนบ`
  - อัปโหลดได้ไม่จำกัดจำนวนไฟล์
  - จำกัดขนาดแบบรายไฟล์ ไฟล์ละไม่เกิน 10 MB
  - frontend รองรับไฟล์รูปภาพและ PDF ใน UI
- `Link`
  - เพิ่มหลังช่อง `เอกสารแนบ`
  - ใช้เก็บ URL เอกสารแนบเพิ่มเติมของจุดตรวจวัด

หมายเหตุ: การเปลี่ยนแปลงนี้เป็น frontend state ชั่วคราว ยังไม่ผูกเข้า payload เดิม

### 2. ตารางโรงงานที่เข้าข่าย

เพิ่มคอลัมน์ `เอกสารแนบ`

- ถ้าไม่มีเอกสารแนบและไม่มี link ให้แสดง `-`
- ถ้ามีเอกสารแนบหรือ link ให้แสดงปุ่ม `เอกสารแนบ (จำนวน)`
- เมื่อกดปุ่มจะแสดง popover/dropdown panel
- รายการใน panel จัดกลุ่มตามจุดตรวจวัด
- แสดงทั้งไฟล์และ link ที่แนบไว้ทั้งหมด
- เมื่อกดรายการที่มี URL จะเปิดในแท็บใหม่

## Field ชั่วคราวที่ frontend ใช้อยู่

ใน state ของแต่ละจุดตรวจวัด frontend ใช้ field ต่อไปนี้:

```json
{
  "attachmentFiles": [],
  "attachmentLink": ""
}
```

`attachmentFiles` ใน frontend ตอนนี้เป็น object ของไฟล์จาก browser จึงยังไม่ใช่รูปแบบ payload สำหรับ backend โดยตรง

## API ที่อาจได้รับผลกระทบ

### อ่านข้อมูลโรงงานที่เข้าข่าย

```text
GET /api/v1/eligible-factories
```

ต้องการให้ response ของ `measurementPoints[]` ส่งข้อมูลเอกสารแนบและ link กลับมา เพื่อให้คอลัมน์ `เอกสารแนบ` แสดงรายการได้ครบ

ตัวอย่างโครงสร้างที่ backend อาจพิจารณา:

```json
{
  "measurementPoints": [
    {
      "pointCode": "SO461",
      "pointName": "H-2050A",
      "systemType": "CEMS",
      "attachmentLinks": [
        {
          "label": "เอกสารอ้างอิง",
          "url": "https://example.com/document"
        }
      ],
      "attachments": [
        {
          "fileName": "document.pdf",
          "fileUrl": "https://example.com/uploads/document.pdf",
          "fileType": "application/pdf",
          "fileSize": 123456
        }
      ]
    }
  ]
}
```

### อ่าน/แก้ไขแบบฟอร์มข้อมูลจุดตรวจวัด

```text
GET /api/v1/monitoring-point-forms
GET /api/v1/monitoring-point-forms/:id
POST /api/v1/monitoring-point-forms
PUT /api/v1/monitoring-point-forms/:id
```

ต้องการให้ backend กำหนด contract สำหรับเอกสารแนบและ link รายจุดตรวจวัด

- response ควรส่งข้อมูลกลับมาเพื่อ prefill ใน bottomsheet ได้
- request payload ยังไม่ได้เปลี่ยนใน frontend รอบนี้
- หากต้องส่งไฟล์จริง backend ต้องกำหนด endpoint หรือ flow สำหรับ upload ไฟล์ก่อน แล้วค่อยให้ frontend ผูก payload ตาม contract ใหม่

## สิ่งที่ backend ต้องพิจารณา

- รูปแบบเก็บไฟล์แนบรายจุดตรวจวัด
- รูปแบบเก็บ link รายจุดตรวจวัด
- จำกัดขนาดไฟล์ที่ backend ด้วยหรือไม่ โดย frontend ตรวจไฟล์ละไม่เกิน 10 MB แล้ว
- ต้องรองรับหลายไฟล์ต่อจุดตรวจวัด
- ต้องระบุว่าเอกสารแนบและ link อยู่ใน field เดียวกันหรือแยก field
- ต้องระบุว่า link มีได้ 1 รายการหรือหลายรายการ

## สถานะปัจจุบันของ frontend

- เพิ่ม UI แล้ว
- เพิ่มคอลัมน์แสดงเอกสารแนบแล้ว
- ยังไม่เปลี่ยน payload ที่ส่งไป backend
- ยังไม่ผูก upload ไฟล์จริงกับ API ใหม่
