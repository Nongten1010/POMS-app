# Frontend Handoff: Connection Request E-form Changes 05082026

เอกสารนี้บันทึกการแก้ไข frontend ในหน้า **ขอเชื่อมต่อ** สำหรับ e-form **เพิ่มจุดตรวจวัด** ทั้งกรณีผู้ประกอบการและเจ้าหน้าที่ เพื่อให้ backend ตรวจ payload/response contract ต่อ

## Scope

- หน้า: ขอเชื่อมต่อ
- ฟอร์ม: เพิ่มจุดตรวจวัด
- ระบบที่กระทบ: CEMS
- Component หลัก: `src/pages/ConnectionRequestPage.jsx`

## สิ่งที่แก้ใน Frontend

### 1. ช่องร้อยละโดยประมาณของเชื้อเพลิง

แบบเดิม:

- ช่อง `primaryFuelPercent` และ `secondaryFuelPercent` กรอกได้เสมอ

แบบใหม่:

- ถ้าไม่ได้เลือก `primaryFuel` ช่อง `primaryFuelPercent` จะ disabled
- ถ้าไม่ได้เลือก `secondaryFuel` ช่อง `secondaryFuelPercent` จะ disabled
- เมื่อ disabled browser จะไม่ส่ง field นั้นใน form submit และ frontend จะตีค่าเป็น `null`

ผลต่อ backend/payload:

- backend ควรรองรับ `primaryFuelPercent: null`
- backend ควรรองรับ `secondaryFuelPercent: null`
- ไม่ควรบังคับ percent ถ้าไม่มีการเลือกเชื้อเพลิงหลัก/รอง

### 2. ช่องร่วมกับปล่อง

แบบเดิม:

- Label: `ร่วมกับปล่อง`
- Field: `sharedStackCode`

แบบใหม่:

- Label: `ร่วมกับปล่อง (รหัสจุดตรวจวัด)`
- Field เดิม: `sharedStackCode`
- เงื่อนไขแสดงผลเดิมยังเหมือนเดิม คือซ่อนเมื่อ `timeSharingParameters` มีค่า `ไม่มี`

ผลต่อ backend/payload:

- ไม่เปลี่ยน key payload
- ความหมายของ field ชัดเจนขึ้นว่าเป็นรหัสจุดตรวจวัดของปล่องที่ใช้ร่วมกัน

### 3. ช่องพารามิเตอร์ที่ได้รับการยกเว้นตามประกาศฯ ข้อ

แบบเดิม:

- อยู่ต่อจาก `requestedParameters`
- เป็น TagInputField
- Field: `exemptedParameterRegulationClauses`
- รูปแบบค่าที่ frontend ส่งเดิมเป็น array/string list

แบบใหม่:

- ย้ายไปอยู่ต่อจากช่อง `legalAnnexNo` หรือหลังกลุ่มเข้าข่ายตามบัญชีแนบท้ายลำดับที่
- เปลี่ยนเป็น dropdown ค่าเดียว
- ตัวเลือก:
  - `ไม่มี`
  - `4(1)`
  - `4(2)`
  - `11(3)`
  - `อื่นๆ`
- เมื่อเลือก `อื่นๆ` จะแสดงช่อง text เพิ่ม:
  - Label: `ระบุ ข้อตามประกาศ`
  - Field: `exemptedParameterRegulationClauseOther`

ผลต่อ backend/payload:

- `exemptedParameterRegulationClauses` เปลี่ยนจากหลายค่าเป็นค่าเดียวแบบ string หรือ `null`
- เพิ่ม field ใหม่ `exemptedParameterRegulationClauseOther`
- ถ้าเลือก `อื่นๆ` backend ควรอ่านค่าระบุเพิ่มเติมจาก `exemptedParameterRegulationClauseOther`
- ถ้าเลือกค่าอื่น ช่อง `exemptedParameterRegulationClauseOther` อาจไม่ถูกส่งหรือเป็น `null`

## หมายเหตุ

- การแก้ frontend รอบนี้ตั้งใจไม่ยึด payload/response เดิมตามคำสั่งงาน
- backend ควรตรวจ contract อีกครั้งก่อนล็อก schema สุดท้าย

## API ที่อาจได้รับผลกระทบ

รายการนี้เป็น API ที่ frontend อาจส่ง payload หรืออ่าน response ที่มี field เหล่านี้ จึงควรให้ backend ตรวจ contract/validation เพิ่มเติม

| API | เหตุผลที่อาจได้รับผลกระทบ |
| --- | --- |
| `POST /api/v1/cems-wpms-requests/measurement-points` | ใช้บันทึก e-form เพิ่มจุดตรวจวัดของผู้ประกอบการ field `primaryFuelPercent`, `secondaryFuelPercent`, `exemptedParameterRegulationClauses`, `exemptedParameterRegulationClauseOther`, `sharedStackCode` อาจอยู่ใน `measurementPoints[].details` |
| `POST /api/v1/cems-wpms-requests/direct-connections` | ใช้กรณีเจ้าหน้าที่เพิ่มจุดและเชื่อมต่อทันที ใช้ form/detail shape ใกล้เคียงกับเพิ่มจุดตรวจวัด จึงอาจได้รับผลจาก field ชุดเดียวกัน |
| `PUT /api/v1/cems-wpms-requests/:id/form` | ใช้แก้ไข/ส่งคำขอเดิมอีกครั้ง หากคำขอเป็นประเภทเพิ่มจุดตรวจวัด backend ควรรองรับ shape ใหม่เหมือน endpoint เพิ่มจุดตรวจวัด |
| `GET /api/v1/cems-wpms-requests/:id/detail` | ใช้เปิดดู/เติมข้อมูลกลับเข้าแบบฟอร์มและ PDF preview ควรคืนค่า `exemptedParameterRegulationClauses` เป็น string หรือคืน field ใหม่ให้ frontend map ได้ |
| `GET /api/v1/cems-wpms-requests/factories/:factoryId/general` | ถ้า backend เติม default ของรายละเอียดจุดตรวจวัด CEMS ลงฟอร์มจาก API นี้ ควรตรวจว่า default field ใหม่/field ที่เปลี่ยนรูปแบบยัง map ได้ถูกต้อง |

### Field ที่ควรตรวจร่วมกับ API

- `primaryFuelPercent`: ควร nullable เมื่อไม่ได้เลือก `primaryFuel`
- `secondaryFuelPercent`: ควร nullable เมื่อไม่ได้เลือก `secondaryFuel`
- `sharedStackCode`: key เดิม แต่ label ใหม่หมายถึงรหัสจุดตรวจวัดของปล่องที่ใช้ร่วมกัน
- `exemptedParameterRegulationClauses`: จากเดิมหลายค่า เปลี่ยนเป็นค่าเดียว เช่น `ไม่มี`, `4(1)`, `4(2)`, `11(3)`, `อื่นๆ`
- `exemptedParameterRegulationClauseOther`: field ใหม่ ใช้เมื่อ `exemptedParameterRegulationClauses = อื่นๆ`

## Eligible Factories: Monitoring Point Bottom Sheet

หน้า **โรงงานที่เข้าข่าย** เมนูย่อย **โรงงานที่เข้าข่าย** ใน bottomsheet **เพิ่ม/แก้ไข ข้อมูลจุดตรวจวัด** มีการเพิ่ม field ใหม่ใน frontend โดยยังไม่ยึด payload/response เดิม

### Field ที่เพิ่มใน bottomsheet

| UI label | Frontend field/key ปัจจุบัน | ประเภท UI | หมายเหตุ |
| --- | --- | --- | --- |
| พารามิเตอร์ที่ติดตั้งแบบ Time sharing | `timeSharingParameters` | multiselect | ใช้ตัวเลือกพารามิเตอร์ตามชนิดจุดตรวจวัด CEMS/WPMS และมีตัวเลือก `ไม่มี` เป็นตัวแรก |
| ร่วมกับปล่อง (รหัสจุดตรวจวัด) | `sharedStackCode` | text | ซ่อนเมื่อ `timeSharingParameters` มีค่า `ไม่มี` |
| สถานะ | `monitoringPointStatus` | dropdown | เก็บสถานะรายจุดตรวจวัด เพื่อให้ backend นำไปสรุปสถานะระดับโรงงาน |

### API ที่อาจได้รับผลกระทบจาก bottomsheet

| API | เหตุผลที่อาจได้รับผลกระทบ |
| --- | --- |
| `GET /api/v1/monitoring-point-forms?factoryRegistrationNoNew=...` | ใช้โหลดรายการ form เดิมของโรงงาน เพื่อนำ field `timeSharingParameters`, `sharedStackCode`, `monitoringPointStatus` กลับมาเติม bottomsheet |
| `GET /api/v1/monitoring-point-forms/:id` | ใช้โหลดรายละเอียดจุดตรวจวัดเดิม ควรคืน field ใหม่ใน `points[]` หรือใน `details` ของแต่ละ point |
| `POST /api/v1/monitoring-point-forms` | ใช้บันทึกข้อมูลจุดตรวจวัดครั้งแรก ควรรองรับ field ใหม่ใน `points[]` |
| `PUT /api/v1/monitoring-point-forms/:id` | ใช้แก้ไขข้อมูลจุดตรวจวัดเดิม ควรรองรับ field ใหม่ใน `points[]` |

## Eligible Factories: Table Status Columns

หน้า **โรงงานที่เข้าข่าย** เมนูย่อย **โรงงานที่เข้าข่าย** ตาราง **โรงงานที่เข้าข่าย** เพิ่มคอลัมน์ใน frontend แล้ว แต่ยังไม่ใส่ข้อมูลจริง

### คอลัมน์ที่เพิ่ม

| ตำแหน่ง | คอลัมน์ใหม่ | Frontend field/key placeholder | หมายเหตุ |
| --- | --- | --- | --- |
| หลังคอลัมน์ CEMS | สถานะ CEMS | `cemsConnectionStatusSummary` | ตอนนี้แสดง `-` ก่อน รอ backend ส่งข้อมูล |
| หลังคอลัมน์ WPMS | สถานะ WPMS | `wpmsConnectionStatusSummary` | ตอนนี้แสดง `-` ก่อน รอ backend ส่งข้อมูล |

### เงื่อนไขสรุปสถานะที่ต้องการจาก backend

ให้ backend สรุปจาก `monitoringPointStatus` ของทุกจุดตรวจวัดในโรงงานนั้น แยกตามระบบ CEMS/WPMS

| สถานะสรุป | เงื่อนไข |
| --- | --- |
| เชื่อมต่อครบถ้วน | ทุกจุดตรวจวัดของระบบนั้นมี `monitoringPointStatus = เชื่อมต่อครบแล้ว` |
| ได้รับยกเว้นทั้งหมด | ทุกจุดตรวจวัดของระบบนั้นมี `monitoringPointStatus = ได้รับการยกเว้นทั้งหมด` |
| ยังไม่แล้วเสร็จ | เงื่อนไขอื่นๆ นอกจาก 2 เงื่อนไขด้านบน |

### API ที่อาจได้รับผลกระทบจากคอลัมน์สถานะ

| API | เหตุผลที่อาจได้รับผลกระทบ |
| --- | --- |
| `GET /api/v1/eligible-factories` | ใช้แสดงตารางโรงงานที่เข้าข่าย ควรเพิ่มข้อมูลสรุปสำหรับคอลัมน์ `cemsConnectionStatusSummary` และ `wpmsConnectionStatusSummary` หรือชื่อ field ที่ backend กำหนด |
| `GET /api/v1/eligible-factories/candidates` | ถ้าต้องการให้ข้อมูลสถานะติดมากับโรงงานทั้งหมดก่อนเลือกเข้าข่าย อาจต้องเพิ่ม field สรุปสถานะรูปแบบเดียวกัน แต่ frontend รอบนี้ยังใช้เฉพาะตารางโรงงานที่เข้าข่าย |

### หมายเหตุเพิ่มเติม

- ปุ่ม `ลบจุดนี้` ใน bottomsheet เพิ่ม dialog ยืนยันก่อนลบ เฉพาะ frontend ไม่กระทบ API โดยตรง
- frontend ยังไม่ผูกข้อมูลจริงให้คอลัมน์ `สถานะ CEMS` และ `สถานะ WPMS` จนกว่า backend จะส่ง response structure ที่ชัดเจน
