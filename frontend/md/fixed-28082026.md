# fixed-28082026

เอกสารนี้บันทึกการแก้ไขฝั่ง frontend ของเมนู **สิทธิ์การใช้งาน** เพื่อให้ backend ใช้อ่านผลกระทบกับ API, payload และ response ภายหลัง

## ส่วนที่แก้ไขใน frontend

### Dialog เพิ่มผู้ใช้งาน และแก้ไขสิทธิ์การใช้งาน

- ช่อง **สิทธิ์ในระบบ**
  - เพิ่มตัวเลือก `สำนักงานกำกับกิจการพลังงาน (กกพ.)` ไว้ลำดับสุดท้าย
  - value ที่ frontend ใช้: `erc_office`
  - เอาตัวเลือก `ประชาชน ไม่ login` ออกจาก dropdown
- ปุ่ม `ยกเลิก`
  - เปลี่ยนเป็นปุ่มแบบมี border

### Dialog แก้ไขสิทธิ์การใช้งาน

- ถ้า `user.accountType = "api"` ช่องต่อไปนี้แก้ไขไม่ได้
  - `username`
  - `fullName`
  - `department`
  - `lineNameTh`
  - `levelNameTh`
- เพิ่มปุ่ม `สิทธิ์เริ่มต้น`
  - ปุ่มนี้ใช้ reset หน้าฟอร์มสิทธิ์กลับไปตามค่าที่ frontend โหลดเข้ามาใน dialog
- ย้ายกลุ่มปุ่ม footer ของ dialog มาอยู่ตรงกลาง

### Permission section

- section อื่นๆ ยกเว้น `ข้อมูลพื้นฐาน` เพิ่มตัวเลือกในช่อง `ข้อมูล`
  - `โรงงานประเภท 88`
  - value ที่ frontend ใช้: `FACTORY_TYPE_88`
- section `จัดการสิทธิ์การใช้งาน`
  - ช่อง `ข้อมูล` มีตัวเลือกเฉพาะ
    - `อนุญาต` ส่งค่า `ALL`
    - `ไม่อนุญาต` ส่งค่า `null`
- section `จัดการโรงงานที่เข้าข่าย (Admin)`
  - เปลี่ยนชื่อเป็น `โรงงานที่เข้าข่าย`
  - เพิ่ม checkbox
    - `มีสิทธิ์ใช้งาน` ส่ง action `view`
    - `การแก้ไข` ส่ง action `edit`
    - `อนุมัติ/อนุญาต` ส่ง action `approve`
  - เพิ่มช่อง `ภาค` และ `จังหวัด`
  - ใช้เงื่อนไขเหมือน section หน้าหลัก:
    - ถ้า `ข้อมูล = ภาค` ต้องเลือก `ภาค`
    - ถ้า `ข้อมูล = จังหวัด` ต้องเลือก `จังหวัด`

## API ที่ได้รับผลกระทบ

### GET /api/v1/users

ใช้โหลดรายการผู้ใช้งานในตารางหน้าเมนูสิทธิ์การใช้งาน

Frontend อ่าน field หลัก:

| fieldname | desc | type |
| --- | --- | --- |
| id | รหัสผู้ใช้ | number |
| accountType | แหล่งบัญชี เช่น `poms`, `api` | text |
| identityProvider | provider ของบัญชี | text |
| username | username | text |
| fullName | ชื่อ-นามสกุล | text |
| department | สังกัด | text |
| lineNameTh | ตำแหน่ง | text |
| levelNameTh | ระดับ | text |
| roles | role code หลัก | text |
| roleCodes | role code array | array |
| isActive | สถานะบัญชี | boolean |

### GET /api/v1/users/:id

ใช้โหลดข้อมูลก่อนเปิด dialog แก้ไขสิทธิ์การใช้งาน

Frontend คาดหวัง response:

| fieldname | desc | type |
| --- | --- | --- |
| user | ข้อมูลผู้ใช้ | object |
| permissions | grouped effective permissions | object |

Field ที่มีผลกับ UI:

| fieldname | desc | type |
| --- | --- | --- |
| user.accountType | ถ้าเป็น `api` จะ lock ช่องข้อมูลส่วนตัว | text |
| user.username | username | text |
| user.fullName | ชื่อ-นามสกุล | text |
| user.department | สังกัด | text |
| user.lineNameTh | ตำแหน่ง | text |
| user.levelNameTh | ระดับ | text |
| user.roleCodes | role ที่เลือก | array |
| user.roles | role ที่เลือก กรณีเป็น text | text |
| user.isActive | สถานะบัญชี | boolean |
| permissions.<module>.data | scope ของข้อมูล | text/null |
| permissions.<module>.region | ภาคของ scope | text/null |
| permissions.<module>.province | จังหวัดของ scope | text/null |
| permissions.<module>.<action> | สิทธิ์แต่ละ action | boolean |

### POST /api/v1/users/local-accounts

ใช้ตอนเพิ่มผู้ใช้งานจาก dialog เพิ่มผู้ใช้งาน

Payload ปัจจุบันที่ frontend ส่ง:

```json
{
  "user": {
    "fullName": "ชื่อ-นามสกุล",
    "username": "username",
    "department": "สังกัด หรือ empty string",
    "lineNameTh": "ตำแหน่ง หรือ empty string",
    "levelNameTh": "ระดับ หรือ empty string",
    "roleCodes": ["diw_central"],
    "isActive": true,
    "userType": "officer",
    "password": "password"
  },
  "permissions": {}
}
```

Dropdown `roleCodes[0]` ที่ frontend เปิดให้เลือก:

| value | label |
| --- | --- |
| public_user | ประชาชน login |
| factory_operator | โรงงาน (ผู้ประกอบการ) |
| diw_central | กรอ. |
| provincial_office | สอจ. |
| industrial_estate | กนอ. |
| monitoring_kpm | เจ้าหน้าที่ศูนย์เฝ้า (กฝม.) |
| monitoring_5_centers | เจ้าหน้าที่ศูนย์เฝ้า (5 ศูนย์) |
| center_director | ผอ.ศูนย์ |
| kpm_director | ผอ.กฝม. |
| kwp_director | ผอ.กวภ. |
| admin | Admin |
| erc_office | สำนักงานกำกับกิจการพลังงาน (กกพ.) |

### PATCH /api/v1/users/:id

ใช้ตอนบันทึก dialog แก้ไขสิทธิ์การใช้งาน

Payload กรณีบัญชี POMS/local:

```json
{
  "user": {
    "fullName": "ชื่อ-นามสกุล",
    "username": "username",
    "department": "สังกัด หรือ null",
    "lineNameTh": "ตำแหน่ง หรือ null",
    "levelNameTh": "ระดับ หรือ null",
    "roleCodes": ["diw_central"],
    "isActive": true,
    "password": "password หรือ empty string"
  },
  "permissions": {
    "dashboard": {
      "data": "ALL",
      "region": null,
      "province": null,
      "view": true,
      "favorite": true,
      "search": true,
      "advanced_search": true,
      "statistics": true,
      "export": true
    }
  }
}
```

Payload กรณีบัญชีจาก API:

```json
{
  "user": {
    "accountType": "api",
    "source": "api",
    "username": "username เดิมจาก response",
    "fullName": "ชื่อเดิมจาก response",
    "roleCodes": ["diw_central"],
    "isActive": true
  },
  "permissions": {}
}
```

ค่า `permissions.<module>.data` ที่ frontend อาจส่ง:

| value | label |
| --- | --- |
| ALL | ทั้งหมด |
| IN_PROVINCE | จังหวัด |
| IN_REGION | ภาค |
| IN_ESTATE | นิคม |
| OWN_FACTORY | โรงงานตนเอง |
| null | ไม่อนุญาต |
| FACTORY_TYPE_88 | โรงงานประเภท 88 |

สำหรับ section `จัดการสิทธิ์การใช้งาน` ค่า `permissions.permissions.data` จะมีเฉพาะ:

| value | label |
| --- | --- |
| ALL | อนุญาต |
| null | ไม่อนุญาต |

Module/action ที่ frontend ส่งใน `permissions`:

| module | actions |
| --- | --- |
| dashboard | view, favorite, search, advanced_search, statistics, export |
| factories | view, edit, approve |
| connection | view, edit, approve |
| kwp_forms | view, edit, approve |
| bod_cod_errors | view, edit, approve |
| notifications | view, view_status, edit, approve |
| statistics | view |
| conditional_search | view |
| helpdesk | view |
| feedback | view |
| laws | view, edit |
| faq | view, edit |
| chat | view, edit |
| permissions | view |
| eligible_factories | view, edit, approve |

### DELETE /api/v1/users/:id

ใช้ลบผู้ใช้งานจากตาราง

Payload: ไม่มี

## จุดที่ backend อาจต้องรับทราบ

- เพิ่ม role value ใหม่ `erc_office`
- เพิ่ม scope/data value ใหม่ `FACTORY_TYPE_88`
- section `eligible_factories` จากเดิมมีแค่ `view` เปลี่ยนเป็น `view`, `edit`, `approve`
- section `eligible_factories` เริ่มส่ง `data`, `region`, `province`
- section `permissions` จำกัดตัวเลือก `data` เป็น `ALL` หรือ `null`
- ในกรณีบัญชีจาก API frontend lock field ข้อมูลส่วนตัว แต่ยังส่ง `username` และ `fullName` เดิมจาก response ใน payload
