# Frontend Handoff: แจ้งแบบ กวภ.01–05

เอกสารนี้บันทึกสิ่งที่ frontend เปลี่ยนและข้อมูลที่ต้องใช้จาก backend ไม่ใช่ API contract ที่ยืนยันว่ารองรับแล้ว การแก้ไขครั้งนี้ไม่ได้แก้ backend และยังไม่ได้ทดสอบส่งข้อมูลใหม่เข้า production

API contract ที่ backend ดูแลอยู่ที่ [แจ้งแบบ กวภ.01–05](../../docs/backend/api/menus/kwp-forms/README.md) เมื่อ backend รองรับแล้ว ให้ปรับเอกสาร canonical และ OpenAPI ที่เกี่ยวข้องด้วย

## สิ่งที่เปลี่ยนใน Frontend

| แบบฟอร์ม | การเปลี่ยนแปลง |
| --- | --- |
| กวภ.01 และ กวภ.03 | เพิ่มเอกสารแนบหนึ่งชุด เลือกหลายไฟล์ได้ และ Link เอกสารแนบ ใช้รูปแบบช่องแนบไฟล์และลิงก์เดียวกับ กวภ.05 |
| กวภ.02 และ กวภ.04 | คงเอกสารสองชุดเดิม ได้แก่ ภาพถ่ายขณะเก็บตัวอย่างและรายงานผลห้องปฏิบัติการ เพิ่ม Link แยกแต่ละชุด |
| กวภ.02 และ กวภ.04 | เพิ่มรายงานครั้งที่และปี พ.ศ. แถวเดียวกัน ก่อนรหัสจุดตรวจวัด ปีเริ่มต้นเป็นปีปัจจุบันตามเวลาไทย และ PDF แสดง เช่น `รายงานครั้งที่ : 1/2569` |
| กวภ.01–05 | ผู้ประกอบการกดยกเลิกคำขอได้ทุกสถานะ ยกเว้นผ่านการพิจารณาและยกเลิก ต้องยืนยันใน dialog ก่อนเรียก API ทุกครั้ง |
| PDF กวภ.01–05 | แสดงเลขที่ คำว่า **ผ่านการพิจารณา** หลังเลขที่เมื่ออนุมัติแล้ว วันที่ยื่นคำขอ และวันที่ในช่องลายเซ็น |

**ไม่แสดงผู้แก้ไขข้อมูลที่หัวกระดาษ PDF** ชื่อผู้จัดทำรายงานในแบบฟอร์ม (`reporterName`) ยังคงแสดงในช่องลายเซ็น และตำแหน่งใช้ `reporterPosition`

### การจัดหน้า PDF

- ใช้แม่แบบ PDF เดิมเป็นฐาน คงเส้นกรอบ เส้นประ ความกว้างคอลัมน์ ตำแหน่ง checkbox และรูปแบบช่องลายเซ็น ไม่ใช้ตารางรูปแบบใหม่แทนแม่แบบเดิม
- ข้อ 4.4 ของ กวภ.03 คงหัวข้อและตัวเลือก BOD, COD, flow, watt ไว้ในบรรทัดเดียวกัน
- PDF กวภ.01–05 ขยายความสูงช่องตามเนื้อหาและรักษาการเว้นบรรทัด ไม่ตัดข้อความเพื่อให้พอดีกับความสูงเดิม
- หาก section ใส่ได้ในหนึ่งหน้า แต่พื้นที่หน้าปัจจุบันไม่พอ จะย้ายทั้ง section ไปหน้าใหม่
- หาก section ยาวเกินหนึ่งหน้า จะแบ่งตามข้อย่อยหรือแถวตาราง โดยให้หัวข้ออยู่กับเนื้อหา และแสดงหัวตารางซ้ำในหน้าถัดไป
- เฉพาะกรณีข้อความในข้อเดียวหรือแถวเดียวสูงเกินพื้นที่หนึ่งหน้า จึงแบ่งข้อความต่อหน้าโดยไม่ทิ้งข้อมูล
- ชุดลายเซ็นย้ายไปด้วยกันเมื่อพื้นที่ไม่พอ รายการไฟล์แนบและ Link ตัดบรรทัดและต่อหน้าได้
- เป็นการจัดหน้า PDF ฝั่ง frontend เท่านั้น ไม่เพิ่มหรือเปลี่ยนฟิลด์ API จากข้อกำหนดอื่นในเอกสารนี้

## API ที่ได้รับผลกระทบ

ทุก endpoint ในตารางมี prefix `/api/v1`

| Endpoint | สิ่งที่ frontend ต้องการให้รองรับ |
| --- | --- |
| `POST /kwp-form-submissions/kwp01`, `POST /kwp-form-submissions/kwp03` | บันทึกเอกสารแนบชุดเดียวหลายไฟล์และ `attachmentLink` |
| `PATCH /kwp-form-submissions/kwp01/:id`, `PATCH /kwp-form-submissions/kwp03/:id` | เพิ่ม ลบ แทนที่ไฟล์ และแก้ไขหรือล้างลิงก์ |
| `POST /kwp-form-submissions/kwp02`, `POST /kwp-form-submissions/kwp04` | บันทึก `reportRound`, `reportYear`, `samplingPhotoLink`, `labReportLink` |
| `PATCH /kwp-form-submissions/kwp02/:id`, `PATCH /kwp-form-submissions/kwp04/:id` | แก้ไขรายงานครั้งที่ ปี พ.ศ. และลิงก์ทั้งสองชุด |
| `GET /kwp-form-submissions/kwp01/:id` ถึง `GET /kwp-form-submissions/kwp05/:id` | คืนข้อมูลสำหรับเปิดดู PDF และแก้ไข รวมถึงฟิลด์ใหม่ของแต่ละแบบ เอกสารแนบ และ metadata ที่ระบุด้านล่าง |
| `POST /kwp-form-submissions/attachments` | รับไฟล์ชุดทั่วไปชนิด `GENERAL` สำหรับ กวภ.01/03 และคืน metadata ที่นำไปบันทึกกับคำขอได้ |
| `POST /kwp-form-submissions/:id/workflow-actions` | รับ `{ "action": "CANCEL" }` จากผู้ประกอบการที่มีสิทธิ์ในคำขอ ตรวจสถานะล่าสุดก่อนยกเลิก |
| `GET /kwp-form-reports/requests` | คืนสถานะล่าสุดหลังยกเลิก รวมถึง `id`, `requestNo`, `statusCode`/`status`/`statusLabel` สำหรับแสดงรายการและกำหนดสิทธิ์ปุ่ม |
| `POST /kwp-form-submissions/kwp01/:id/resubmit` ถึง `POST /kwp-form-submissions/kwp05/:id/resubmit` | ส่งคำขอที่แก้ไขแล้วต่อได้ โดยไม่ทำข้อมูลใหม่หรือไฟล์ที่บันทึกผ่าน PATCH สูญหาย รูปแบบ body ของ resubmit ไม่ได้เปลี่ยน |

การสร้าง/แก้ไข กวภ.05 ไม่ได้เพิ่มฟิลด์ payload ใหม่ แต่การอ่าน PDF และเงื่อนไขยกเลิกใช้กติกาใหม่ร่วมกับแบบอื่น

## ข้อมูลเอกสารแนบ กวภ.01 และ กวภ.03

Frontend ส่งฟิลด์ต่อไปนี้ที่ระดับ root ร่วมกับข้อมูลแบบฟอร์มเดิม ตัวอย่างนี้แสดงเฉพาะส่วนที่เพิ่ม ไม่ใช่ payload เต็ม:

```json
{
  "attachmentLink": "https://example.com/report.pdf",
  "attachments": [
    {
      "attachmentType": "GENERAL",
      "originalFileName": "report.pdf",
      "storedFileName": "stored-report.pdf",
      "mimeType": "application/pdf",
      "fileSize": 12345,
      "storagePath": "path-returned-by-upload-api"
    }
  ]
}
```

- อัปโหลดทีละไฟล์ผ่าน multipart โดยใช้ `file` และ `attachmentType=GENERAL` แล้วนำ metadata ที่ได้ไปรวมในคำขอ
- หนึ่งคำขอมีเอกสารทั่วไปหนึ่งชุด แนบได้สูงสุด 5 ไฟล์ รองรับ JPG/JPEG, PNG และ PDF ไฟล์ละไม่เกิน 10 MB และไม่รับไฟล์ว่าง
- Link เป็นตัวเลือก ไม่บังคับกรอก ถ้ากรอกต้องเป็น URL แบบ `http://` หรือ `https://` ค่าว่างส่งเป็น `null`
- การลบไฟล์ทั้งหมดส่ง `attachments: []` การล้างลิงก์ส่ง `attachmentLink: null` backend ต้องไม่คืนค่าเก่ากลับมาแทนโดยอัตโนมัติ
- GET detail ต้องคืน `attachments` และ `attachmentLink` เพื่อเติมฟอร์มเดิมและแสดง PDF พร้อม metadata ไฟล์และ URL/path ที่ frontend เปิดอ่านได้
- ไฟล์ที่เคยบันทึกแล้วและไม่ได้ลบต้องเก็บไว้ได้โดยไม่ต้องอัปโหลดใหม่

## ข้อมูล กวภ.02 และ กวภ.04

ตัวอย่างเฉพาะฟิลด์ใหม่ที่ระดับ root:

```json
{
  "reportRound": 1,
  "reportYear": 2569,
  "samplingPhotoLink": "https://example.com/sampling.pdf",
  "labReportLink": "https://example.com/lab.pdf"
}
```

- `reportRound` เป็น number จำนวนเต็มมากกว่า 0
- `reportYear` เป็น number ปี พ.ศ. 4 หลัก Frontend ตรวจขั้นต่ำ 2400 และเติมปีปัจจุบันให้ในช่องที่ยังไม่มีค่า ผู้ใช้แก้ปีได้
- ตัวอย่าง `2569` คือปี พ.ศ. ไม่ใช่ ค.ศ. ห้ามบวก 543 ซ้ำเมื่อคืนข้อมูลหรือแสดง PDF
- Link ทั้งสองเป็น optional ล้างค่าได้ด้วย `null` และตรวจ URL เช่นเดียวกับ กวภ.01/03
- เอกสารสองชุดเดิมยังคงใช้ `SAMPLING_PHOTO` และ `LAB_REPORT` ชุดละสูงสุด 5 ไฟล์ ไฟล์ละไม่เกิน 5 MB
- ตำแหน่งไฟล์ใน payload ยังใช้วิธีเดิม คือรวมไฟล์สองชุดใน `measurementItems[0].attachments` ไม่ได้เพิ่มไฟล์ซ้ำทุกแถว ส่วน Link เป็นระดับคำขอ
- GET detail ต้องคืนฟิลด์ใหม่ที่ root และคืนไฟล์แต่ละชนิดให้แยกกลับลงช่องเดิมได้
- PDF ของคำขอเก่าที่ไม่มีรายงานครั้งที่/ปี ไม่ควรถูกตีความเป็นข้อมูลปีปัจจุบันย้อนหลัง การเติมปีอัตโนมัติเป็นค่าเริ่มต้นใน e-form เท่านั้น

## การยกเลิกคำขอ

Frontend เรียก API หลังผู้ใช้กดยืนยันเท่านั้น:

```http
POST /api/v1/kwp-form-submissions/:id/workflow-actions
Content-Type: application/json
Authorization: Bearer <token>
```

```json
{
  "action": "CANCEL"
}
```

- อนุญาตผู้ประกอบการยกเลิกคำขอที่ตนมีสิทธิ์ได้ทุกขั้นตอน รวมถึงสถานะไม่อนุมัติ หากยังไม่ใช่ `APPROVED`/ผ่านการพิจารณา หรือ `CANCELLED`/ยกเลิก
- Backend ต้องตรวจสิทธิ์และสถานะล่าสุดเอง ไม่พึ่งการปิดปุ่มบน frontend และต้องไม่ยกเลิกคำขอที่มีการอนุมัติไปแล้วระหว่างเปิด dialog
- ผลสำเร็จต้องอ่านสถานะยกเลิกได้ทั้ง list/detail และมีเหตุการณ์ยกเลิกในประวัติสถานะ
- หากไม่มีสิทธิ์หรือสถานะเปลี่ยนแล้ว ให้ส่ง error ที่อธิบายได้ผ่านรูปแบบ error ของระบบ เช่น HTTP 403/409 ตาม contract ที่ backend กำหนด
- Frontend ปิดปุ่มซ้ำระหว่างรอ response เมื่อสำเร็จจึงปิด dialog และโหลดตารางใหม่ หากล้มเหลวคง dialog ไว้และแสดงข้อความ error

## ข้อมูลที่ PDF ต้องใช้

| Field | การใช้งาน |
| --- | --- |
| `requestNo` | เลขที่บนหัวกระดาษ |
| `statusCode` หรือสถานะที่เทียบได้กับ `APPROVED`/ผ่านการพิจารณา | แสดงคำว่า **ผ่านการพิจารณา** ต่อจากเลขที่ |
| `submittedAt` | วันที่ยื่นคำขอบนหัวกระดาษและวันที่ในช่องลายเซ็น แสดงเป็นวัน/เดือน/ปี พ.ศ. ตามเวลาไทย |
| `reporterName` | ชื่อผู้จัดทำรายงานในช่องลายเซ็น ไม่แสดงที่หัวกระดาษ |
| `reporterPosition` | ตำแหน่งในช่องลายเซ็น |
| `reportRound`, `reportYear` | รายงานครั้งที่/ปีใน PDF กวภ.02/04 |
| ไฟล์แนบและ Link ของแต่ละแบบ | รายการเอกสารแนบใน preview และ PDF เปิดดู |

`submittedAt` ยังคงเป็นวันที่เวลา ISO ตามระบบ ไม่ใช่ปี พ.ศ. ใน API ส่วน `reportYear` เป็นปี พ.ศ. โดยตรง สำหรับ preview คำขอใหม่ที่ยังไม่มี `submittedAt` frontend ใช้เวลาปัจจุบันชั่วคราว เมื่อเปิดคำขอที่บันทึกแล้วให้ใช้ข้อมูลจริงจาก API

## ขอบเขตการตรวจสอบ

Frontend เพิ่ม automated tests สำหรับเงื่อนไขยกเลิก/ยืนยัน, response สำเร็จและผิดพลาดจำลอง, โครงสร้างฟอร์ม, payload, การเติมข้อมูลกลับจาก detail, ปี พ.ศ., ข้อจำกัดไฟล์ และข้อความ PDF ทั้งห้าแบบ รวมถึงสร้าง PDF ตัวอย่างเพื่อตรวจการจัดวาง

การทดสอบนี้ยังไม่ยืนยันว่า backend production รับฟิลด์ใหม่ได้ ต้องทดสอบ create → detail → edit → resubmit และ cancel กับ backend ที่รองรับแล้ว โดยตรวจว่าไฟล์ ลิงก์ รายงานครั้งที่/ปี และสถานะไม่สูญหายตลอด flow
