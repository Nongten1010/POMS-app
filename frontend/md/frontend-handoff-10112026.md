# Frontend: รายงานตามเงื่อนไขใน กวภ.04

## ขอบเขต

บันทึกการเปลี่ยนแปลง Frontend และฟิลด์ที่เสนอให้ Backend รองรับ ไม่ใช่สัญญา API ที่เผยแพร่แล้ว และยังไม่ได้แก้ Backend ในงานนี้ เอกสาร Backend ปัจจุบันอ้างอิงจาก [ศูนย์เอกสาร Backend](../../docs/backend/README.md)

## การแสดงผล

- เฉพาะ กวภ.04: dialog รายการตรวจวัดมลพิษอากาศจากปล่องระบาย เพิ่ม Dropdown **รายงานตามเงื่อนไข** ก่อนวิธีการตรวจวัดวิเคราะห์
- ตัวเลือกเป็น string: `4(1)`, `4(2)`, `11(3)`, `16` บังคับเลือกต่อรายการ ไม่เลือกค่าเริ่มต้นให้อัตโนมัติ
- ขยายวิธีการตรวจวัดวิเคราะห์จากครึ่งแถวเป็นสองในสามของแถวบน desktop; หน้าจอเล็กแสดงเต็มแถว
- เพิ่มคอลัมน์ในตารางรายการของฟอร์ม ตัวอย่างเอกสาร และตารางข้อ 3 ของ PDF ก่อนวิธีการตรวจวัดวิเคราะห์
- PDF ลดความกว้างคอลัมน์เดิมเล็กน้อย และลดคอลัมน์วิธีการตรวจวัดวิเคราะห์มากกว่า โดยให้ข้อความขึ้นบรรทัดใหม่
- กวภ.02 ใช้ฟอร์มร่วมกัน แต่ไม่มีช่องหรือคอลัมน์ใหม่นี้ และไม่ส่งฟิลด์นี้

## Payload ที่เปลี่ยน

Base URL: `https://d-poms.diw.go.th/api/v1`

| API | การเปลี่ยนแปลงจาก Frontend |
| --- | --- |
| `POST /kwp-form-submissions/kwp04` | เพิ่ม `measurementItems[].reportCondition` |
| `PATCH /kwp-form-submissions/kwp04/:id` | เพิ่มฟิลด์เดียวกันเมื่อบันทึกการแก้ไข |
| `POST /kwp-form-submissions/kwp04/:id/resubmit` | ไม่เปลี่ยน payload; ส่งหลัง PATCH สำเร็จตามขั้นตอนเดิม |

ตัวอย่างเฉพาะส่วนที่เพิ่ม (ไม่ใช่ payload เต็ม):

```json
{
  "measurementItems": [
    { "pollutant": "CO (ppm)", "reportCondition": "4(1)" }
  ]
}
```

## Response ที่ Frontend เตรียมอ่าน

`GET /kwp-form-submissions/kwp04/:id`: อ่าน `measurementItems[].reportCondition` เพื่อเปิดแก้ไข ดูเอกสาร และสร้าง PDF โดยแต่ละรายการอาจเลือกเงื่อนไขต่างกัน

รายการเก่าที่ไม่มีฟิลด์นี้ยังเปิดดูได้ แสดงขีดในตาราง/PDF และไม่มีการเดาค่าให้ เมื่อนำมาแก้ไขต้องเลือกค่าให้ทุกรายการก่อนส่ง

## Validation และสิ่งที่ต้องรองรับร่วมกัน

- Frontend ตรวจค่าจากตัวเลือกทั้งสี่ตอนบันทึก dialog ก่อนเปิดตัวอย่าง และก่อนส่งแบบ รวมถึง payload builder
- ข้อกำหนดใหม่นี้ไม่เปลี่ยนกติกาจำนวนรายการตรวจวัดเดิม
- Backend ต้องยืนยันและรองรับฟิลด์ที่เสนอในการรับ บันทึก และคืนค่าของ กวภ.04 พร้อม validation ฝั่ง Backend และปรับเอกสาร API/OpenAPI ที่เป็นแหล่งอ้างอิงกลาง
- ยังไม่ได้ยืนยันว่า API production รับฟิลด์ใหม่นี้แล้ว หากยังไม่รองรับอาจปฏิเสธหรือตัดฟิลด์ออก จึงต้องประสานการเปิดใช้งาน
